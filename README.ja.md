# SpecLingua

[English](README.md)

**SpecLingua（SL）** は、業務システムの仕様を人とAIが共有するための規約と、その規約に従うツール群です。Excel や Word の設計書と、それをレビューして合意する運用がすでにある現場で、設計書を置き換えずに、AIが変更の起草・検査・追跡を行えるようにすることを目的としています。

状態：**v0.0.1、ドラフト**。実案件での試行はまだ行っていません。文書に書いてあるのは「こうする」という設計であり、「こうなった」という実績ではありません。

## 何をするものか

- **既存の設計書を正本のまま維持する。** AIは設計書を忠実に変換した Markdown を読み、原本はそのままの場所に残ります。
- **今回の変更を改修仕様書に記録する。** 変更前の基準、変更項目、変更しない範囲、未決事項、検証条件、反映状況を1つの文書に書きます。
- **根拠と判断を分ける。** AIが起草した記述には由来（`stated`＝明記／`observed`＝観測／`inferred`＝推測／`unverified`＝未確認）を付けます。「確定」になるのは人が判断したときだけで、その判断は現場で使っている台帳に記録します。
- **確認を三つに分ける。** 形式・参照・版・対応関係はスクリプトが検査し、漏れや根拠の弱さはAIレビューが指摘し、範囲・業務条件・受け入れは人が決めます。
- **利用者に形式の学習を求めない。** 利用者は依頼と資料を渡し、起草された本文を普通の文章として直し、問いに答えます。ID・参照・管理情報はツールが扱います。

## 開発ハーネスとの関係

SpecLingua が定めるのは、AI駆動開発のループを回す前の「仕様の整え方」です。人が決めるルール、AIが示すべき根拠、推測せずに人へ返すべき問いを定義します。ループそのもの（AIによる実行、自動チェック、品質ゲート、人の受け入れ）は、姉妹レポジトリ **[ai-dev-harness](https://github.com/hirofumi-kowari/ai-dev-harness)** で説明しています。
